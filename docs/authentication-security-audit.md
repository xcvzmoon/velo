# Authentication security audit

This audit reviews Velo's outbound API authentication: Basic, Bearer, API keys, OAuth client credentials, and authorization code with PKCE. It covers the shared HTTP engine, Tauri command boundary, OS credential operations, cached Vue request tabs, and credential handling in saved tests and collections.

## Standards and trust boundary

The protocol review uses [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html) for OAuth security, [RFC 8252](https://www.rfc-editor.org/rfc/rfc8252.html) for native applications, [RFC 7636](https://www.rfc-editor.org/rfc/rfc7636.html) for PKCE, and [RFC 9207](https://www.rfc-editor.org/rfc/rfc9207.html) for issuer identification. HTTP authentication and token semantics follow [RFC 7617](https://www.rfc-editor.org/rfc/rfc7617.html), [RFC 6750](https://www.rfc-editor.org/rfc/rfc6750.html), and [RFC 6749](https://www.rfc-editor.org/rfc/rfc6749.html).

The user chooses the API target and trusted OAuth issuer/endpoints explicitly. Velo is an API client, so arbitrary user-selected API hosts remain supported. OAuth endpoints must use HTTPS. Remote HTTP requests cannot carry recognized authentication inputs; literal loopback IPs permit local development. Custom request data and usage notes can still contain private information that automatic credential-name rules cannot identify.

## Verified behavior

PKCE uses a random S256 verifier/challenge and random state. State comparison uses the OAuth library's timing-resistant comparison. Authorization opens the system browser; the callback binds only IPv4 loopback on an ephemeral port. Callback requests and token responses have explicit byte limits. Network/callback waits have a deadline, and acquisition never retries or follows token-endpoint redirects implicitly.

Tokens remain behind the native boundary. The frontend receives a secret reference and bounded token metadata. Token requests form-encode client credentials before HTTP Basic encoding; public clients send their client ID in the form. Response decoding rejects malformed, oversized, or unsupported credentials while ignoring unknown extension fields. Refresh remains explicit and binds its stored credential to the configured endpoint, issuer, and client ID.

Credential writes use the application's serialized OS credential boundary. Cancellation and shutdown retain execution admission while those operations settle. An OS dialog cannot be forcibly cancelled by Rust; cleanup waits for the OS operation to return. A failed rollback is reported instead of being treated as successful cancellation. Forgetting a local credential does not revoke the provider's token.

Secret references remain in saved documents. Recognized literal credential fields fail save/export validation before persistence or a file dialog. API responses mask known request values, encoded Basic credentials, common sensitive response fields, and configured JSON pointers before history or export. This policy does not classify arbitrary notes or unknown custom payload fields as secrets. Header placement is preferable for API keys when supported: query keys can enter remote server logs even over HTTPS.

## Verification and limits

Regression tests use local HTTP targets, actual Tauri command dispatch, deferred frontend promises, and credential-store adapters with paused or denied operations. They test observable security behavior without module mocking or accessing real user credentials. The required verification sequence is `pnpm check`, `pnpm typecheck`, `pnpm test`, and `pnpm build`; additional checks include type-aware Oxlint, Clippy with warnings denied, binding consistency, and Rust documentation with warnings denied.

This assurance covers the reviewed source and automated tests. Real-provider consent, provider-specific registration, and actual OS credential dialogs still require manual verification. Authorization-code providers must support RFC 9207 issuer responses and native loopback redirects; unsupported providers fail explicitly. Provider-side refresh rotation cannot be undone by cancelling a local operation. A compromised operating system or deliberately configured malicious issuer/endpoints remains outside this boundary.
