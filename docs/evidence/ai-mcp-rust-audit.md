# AI and MCP Rust design audit

Reviewed on November 8, 2026 against [Microsoft's Pragmatic Rust Guidelines](https://microsoft.github.io/rust-guidelines/). This review covers `src-tauri/src/ai`, `src-tauri/src/ai.rs`, `crates/velo-mcp`, and the shared evidence selector in `velo-contracts`.

| Concern                    | Implementation and audit outcome                                                                                                                                                                                                            | Verification                                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Async work and ownership   | Native review IDs freeze the context and destination. A generation guard owns cancellation and clears the active slot on drop. Session locks are released before network awaits. Blocking credential work uses the existing history worker. | Native review, cancellation, single-flight, and response tests; frontend stale-response tests. |
| Protocol boundaries        | Provider enums select explicit request and response formats. External JSON is bounded and parsed before canonical validation. Refusals, truncation, tool calls, and unavailable evidence references fail without applying a draft.          | Provider request fixtures and malformed-response tests.                                        |
| Secret handling            | Provider keys are scoped to normalized endpoints in the OS credential store. Keyless configurations skip that store. Debug output and infrastructure errors omit payloads and credentials.                                                  | Endpoint scope, keyless, credential-overlap, and content-free error tests.                     |
| Resource limits            | Requests have connection and total deadlines and bounded responses. MCP bounds protocol lines, tool payloads, startup reports, concurrent operations, and proposal quotas.                                                                  | Oversized protocol, report, and proposal tests.                                                |
| File ownership and cleanup | MCP accepts startup-granted regular reports, freezes selected evidence, and publishes new proposal files atomically without replacing existing files. Temporary files are removed on ordinary failures and cancellation before publication. | Stdio evidence snapshots, symlink rejection, non-overwrite, cancellation, and quota tests.     |
| Public APIs and errors     | Shared selectors have rustdoc, executable examples, and explicit input-boundary requirements. Internal adapter details stay crate-private. App failures use stable codes; MCP lifecycle errors do not echo input.                           | Workspace doctests, warning-free rustdoc, strict Clippy.                                       |

The review corrected keyless credential-store access, empty-key overlap checks, Gemini request fields, provider refusal and thought handling, endpoint validation, and binding submissions to the reviewed destination. The final implementation does not use model output to authorize execution or raise local resource budgets.

Cancellation cannot recall data already received by a provider. A credential operation can finish after its caller's wait deadline. Cancellation after atomic proposal publication can leave the completed file. These behaviors are documented rather than presented as rollback guarantees.

Local protocol fixtures verify request construction and response handling. They do not establish live account eligibility, provider terms compliance, model availability, or cross-platform credential-store behavior.
