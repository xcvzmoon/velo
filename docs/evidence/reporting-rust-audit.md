# Baseline reporting Rust audit

Scope: the Rust code added or changed for [issue #17](https://github.com/xcvzmoon/velo/issues/17). The review uses Microsoft's [Pragmatic Rust Guidelines, version 2026.6](https://microsoft.github.io/rust-guidelines/guidelines/checklist/). It does not certify unrelated code or platforms.

| Guidance                                       | Finding and correction                                                                                                                                                                                                                                                                                               | Evidence                                                                         |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| M-FFI-TRANSLATES, M-BALANCED-MODULES           | Comparison arithmetic, verdicts, and exporters belong outside Tauri. They live in `velo-contracts::reports`; exporters have a separate module. Desktop commands handle storage, dialogs, and writes.                                                                                                                 | Contract integration tests exercise the shared API without a desktop runtime.    |
| M-STRONG-TYPES, M-STATIC-VERIFICATION          | Missing origin/workload fields could otherwise match as null values. Compatibility now requires present identities, distinct runs, and matching origin, method, and workload kind. Budget metrics and verdicts use enums. Metadata inserts require a complete value rather than an invalid empty-object SQL default. | Compatibility and missing-identity tests; generated TypeScript contracts.        |
| M-PANIC-IS-STOP, M-UNSAFE                      | User data must not trigger panics or unchecked arithmetic. New production code uses no `unsafe`, `unwrap`, or indexing into vectors. Percentage calculations check zero baselines and finite results. Invalid public API budget inputs cannot pass.                                                                  | Zero/missing population tests, invalid budget tests, unrounded delta tests.      |
| M-MOCKABLE-SYSCALLS                            | Report destination failures need reproducible coverage without a dialog. File writing is isolated from the native dialog and tested with temporary destinations. Failed persistence drops its temporary file.                                                                                                        | Successful replacement, directory destination failure, and missing-parent tests. |
| M-LOG-STRUCTURED                               | Export failures must remain diagnosable without logging native paths. I/O failures log a stable code and error kind; callers receive a safe error.                                                                                                                                                                   | Export failure tests check the public code and absence of the destination path.  |
| M-PUBLIC-DEBUG, M-CANONICAL-DOCS, M-DOC-INLINE | Public report types need inspectable representations and documented semantics. Types derive Debug; APIs have parameter, return, failure, and compiling example sections. Export re-exports use inline documentation.                                                                                                 | Workspace Clippy, rustdoc, and doctests.                                         |
| M-MEM-REUSE, M-INITIAL-CAPACITY                | The history list originally read configuration context twice per entry. It now reads each identity/configuration pair once. Reporting runs on the existing bounded storage admission path, outside measurement workers.                                                                                              | Existing history admission tests and new restart tests.                          |

The correctness review also checked the feature's privacy and evidence requirements. Only allowlisted execution fields enter new history context and its SHA-256 identity. Request data and assertion expectations are omitted. Metadata is explicitly user-authored and bounded. HTML and XML escape user text; XML drops invalid control characters. JUnit carries full safe context in `system-out` and represents aggregate verdicts rather than individual requests.

Incomplete measurements, interrupted or non-completed runs, incomplete history, counter overflow, aggregation interference, out-of-range latency, generator drops, and dataset exhaustion cannot produce a clean regression pass. Missing metrics remain unavailable. Configuration acknowledgement cannot override compatibility or integrity blocks. Stored comparisons keep their baseline dependency after deletion, and deletion invalidates their stored regression verdict.

To reproduce verification, run `pnpm install`, then `pnpm check` → `pnpm typecheck` → `pnpm test` → `pnpm build`. Also run `pnpm lint`, `pnpm bindings:check`, and `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps`. Interactive desktop save dialogs and non-macOS builds require separate acceptance checks.
